## 根因与修复质量

230002（Bot not in chat）的根因链：`_RoutingFeishuClient` 在每次属性访问时按**执行时刻**的 ambient 上下文解析 home（插件 ContextVar → loop 线程共享 thread-local → hermes contextvar → env）。多 profile 并发时 loop 线程的 thread-local 是"最近进入 wrapper 的 turn"的 home——另一 profile 的建卡/flush/封卡路由到错误 bot：cardkit_create 成功（不涉 chat），reply 报 230002。

修复三件套（评价：教科书级）：

| 修复 | 位置 | 评价 |
|---|---|---|
| loop 线程移除 `set_turn_home_thread()`——threading.local 全 loop 共享是竞态根源，路由一律走 ContextVar（任务级隔离），thread-local 仅保留给真 worker 线程（cron 包装器） | gateway.py | ✅ 根因正确，机制讲解清楚 |
| `CardSession.home` 固化 + `_client_for(session)` 会话绑定路由：全部卡片/文本操作从 `self._client.` 换成 `_client_for(session).`，续写会话继承 home，wrapper 显式传 `turn_home` | core.py / linear_mixin.py | ✅ 替换完整（grep 零残留，唯一命中是注释）；无 session 时降级 ambient 兜底（宁可用错身份不吞卡，与既有哲学一致） |
| `on_message_aborted` 去掉 ctrl= kwarg | adapter.py | ✅ 修复 v1.9.0 的反向修复：`@_safe_hook` wrapper 自己注入 ctrl=，调用方再传即 `multiple values for keyword argument 'ctrl'` TypeError（生产 14 天 ×6，/stop 封卡从未送达） |
